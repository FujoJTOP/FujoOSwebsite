内核第一次有了一个可被引用的字节快照。

FOC-0.1.0 是 FujoOS 内核线的第一个 tag，指向 project-dev 的分支顶点：B 段收口（W63a–W70a）加并行开发基础，共六个提交。它的意义不是「内核完成了」——而是从这一版起，验证读数是对着一份可引用的字节说的，而不是对着一句「当前 HEAD」。

这六个提交做了什么

tag 指向的不是一个功能点，是一段收口：把池 arena 迁移、容量探针、T 重算与并行开发基础放在同一个可引用点上。下面按波次先后列，提交短哈希取自 tag 自身的说明。

提交 内容

407d246 W66–W68：load_end 评估（结论是不动）+ T 重算与规则提案 + 池对不遮蔽断言 + 工具链自证

已知边界（诚实记）

  • L3 不等于 L4 —— 换成 Loment 写的代码的只有台账准入的判定层；内核本体仍是 Rust，接口面（0x831A 五个 op 与返回码）一字未动。
  • 矩阵里有一例不稳定 —— box-v1-online 是已知的「连续盒用例抢 COM2 端口」竞态（docs/160 §6.5），harness 重跑即过，本次单独复跑 2/2。归因是环境噪声，不是内核回归——但它是 79 例里唯一不是全绿的那一格，所以写在这里。
  • T 的镜像轴有两种读法 —— 历史序列混了池迁移前 / 后两种布局；同一布局窗口内约 1,148 B/波 ⇒ T ≈ 490 波。两种读法的镜像 T 都远大于 50，不影响任何裁定（docs/161 §7.5(d)）。
口径检查： 「打了第一个 tag」不等于「内核发布」。它是一个可引用的快照，不是一次对外发布；发布与外部审计（M100）仍未达。

怎么拿到它

tag 已经推到远端，在 FujoOS、FujoOS-FujoLang 与 FujoOS-compat 三个仓库里都有同名标签，指向同一个字节快照。

取到那个快照 git fetch --tags && git checkout FOC-0.1.0
读 tag 的全文 git tag -n99 FOC-0.1.0
重跑并行开发门禁 python tools/parallel_gate.py
