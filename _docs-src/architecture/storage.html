存储与 FJFS

划界很清楚：内核只负责块设备访问（经 Ring3 驱动），文件语义全部由 srv_fs 服务实现。这样做的直接后果是——换一个文件系统不需要动内核。

服务端驱动表

驱动 定位
fujo-fs原生文件系统（FJFS），格式化 / 持久化已验证。
ext4Linux 兼容读取。
ntfs只读（计划中）。
exfat / fat共享分区。
hfs+ / apfs-ro只读。

FJFS 的实际状态

项 状态
卷大小4 MiB
格式化 / 持久化已验证
真盘（AHCI/SATA）已验证
多簇写入上限32 KiB 待扩展
最容易被含糊过去的一条： FJFS 的多簇写入目前只支持到 32 KiB 的文件。更大的文件是排队中的工作，不是“已支持”。这条写在这里而不是留给读者去试。

其余部分：ATA PIO 提供最基础的块访问，页缓存与预读在其上收敛性能；存档沙箱提供 8×8 KiB 的隔离写入区；所有服务都可注入检查点，为翻译缓存与进程迁移打底。
