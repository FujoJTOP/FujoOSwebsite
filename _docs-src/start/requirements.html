环境要求

“零第三方依赖”说的是内核本身：它是 no_std、不引用任何外部 crate。构建和验证仍然需要几样宿主工具，下面一条条写清楚，并区分哪些是必需的、哪些只是加速。

必需

工具 为什么需要
Rust nightly + cargo 目标 x86_64-unknown-none 内核是 no_std crate。裸机目标需要 nightly 才有的特性，因此不能只用 stable。
Python 3 构建辅助（ELF 压平）、回归套件、模型评测与图形脚本。tools/ 下的脚本全部是纯 Python，没有 pip 依赖。
QEMU (x86_64) 参考机器。启动与全部回归都在它上面跑；没有开发板、没有真机依赖。

可选

工具 得到什么
WHPX / KVM 硬件虚拟化加速。回归会从 59/59 变成 49/51 —— 差额是两处已记录的平台限制，不是失败。
PowerShell Windows 侧的 scripts/onebuild.ps1 一键构建脚本（hello / gui / game 模板）。
Ollama 只有要复现 AI 层实验时才需要。模型跑在宿主上，不进内核；没有它，系统退回确定性规则照常运行。
关于“真机”： GRUB 启动、AHCI/SATA 持久化与平台检测已在真机上演示过；VBE 视频与 USB 驱动仍未完成。也就是说，真机覆盖是部分的，而且这一点写在明处而不是含混过去。
