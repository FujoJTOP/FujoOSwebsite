盒桥

FUAI 的核心主张是“机制可以在任何宿主上重写”。但有一部分能力天生就不通用：让模型去操作一个 Excel 表格、调用 certutil、驱动记事本——这些谓词指向的是 Windows 宿主上的具体对象，在 Linux 上不存在对应物。

契约因此分成两层

层 内容 差分是否断言
核心层 主机无关的监督原语：能力域、隔离、审计、撤销。46 个原语中的 40 个。 是
宿主扩展层 实现特有部分，盒桥在其中（0x8316–0x8320 一类）。46 个原语中的 6 个。 否
这个划分解决了一个真实的僵局。 如果要求 LinuxFUAI 也“完整覆盖”盒桥，就等于要求在 Linux 上实现一个 Windows 盒——没有意义，而且会让差分器永远红着。把宿主扩展排除在核心契约之外，两个实现才第一次变得“可判定地一致”。

为什么值得保留

盒桥的存在本身是一个有用的事实：它证明了这套机制不只是能管“内核里的动作”，也能管“另一个进程里的 GUI 应用”。能力域、撤销、审计这些概念跨过进程边界之后依然成立——只是具体谓词换了一套。
