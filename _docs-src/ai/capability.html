能力域与审计环

这一页是 S1 机制的实体：一张能力表记住“谁被允许碰什么”，一个审计环记住“谁碰了什么”。两者都很小、很笨，这是有意的——它们是唯一不允许出错的部分。

能力域的形状

一个能力域由三样东西定义：一个名字空间、一个有界区间、一个可撤销标志。名字空间说明这块能力属于哪个领域（磁盘块、AI 动作、……），区间说明允许的范围，可撤销标志说明这块能力能不能被收回。

json 形式对象里的能力域 
{"name": "blk_write",
 "domain": "disk[0..4]",   // 名字空间 + 闭区间
 "revocable": true,          // A4：可撤销
 "on_revoke": "fallback"}    // 撤销后退回确定性规则

撤销是这套设计的关键动作

大多数“AI 安全”方案关注的是“拦住不该做的”。撤销关注的是另一件事：已经建立的能力可以随时被收回，收回后调用返回拒绝，系统退回确定性规则照常运行。这让“模型变坏了怎么办”有一个不需要重启、不需要人工介入的答案。

审计环

项 说明
条目定长记录：时间戳、模型索引、token 数、结果。
写入时机放行与拒绝都写。只记失败会丢掉“系统正常时是什么样”，只记成功会丢掉越权尝试。
消费者内核能力域、A1–A4 验证器、外部 Agent——三方读同一份序列。
持久化在 FUAI-OS 运行时里升级为 append-only 哈希链，跨进程重启保持连续。
一个实证教训： LinuxFUAI 的 l15 带外验证器证明了“域内自证不可信”——库内证书可以被伪造成 0xF，只有用一个独立的带外进程重推导审计序列才发现断档。这条纪律后来成了 FUAI-OS 的硬约束。见 运行时与证据链。
