Loment 的开发组工具已经准备完成，面向开发者社区的日期定在 9 月 20 日。想提前用的人，9 月 15 日可以填 Early Use 表单拿到 Loment 0.1.3.4 Alpha。

「工具准备完成」指的是什么

指的是这一件事：从零开始写 Loment、并在编辑器里用它，这条路上不再需要 Python 解释器。

此前这条路上有三样东西是 Python 写的——格式化器、文档生成器、语言服务。现在三样都有了 Loment 版本，而且判据不是「能跑」：

lomfmt（格式化器）：42 个语料加 4 个边界，再加幂等性，输出与 Python 版逐字节相同。

lomdoc（文档生成器）：43 个语料加 1 个边界，同样逐字节相同。重写过程中反过来抓到参考实现一个真 bug——注入的 Result 枚举带着 prelude 的行号，于是它会把上文某条 capability 的注释当成自己的文档。

loment_lsp（语言服务）：补全、跳转定义、改动后诊断。安装是一条命令 scripts/install-lsp.ps1，由种子加 clang 现场编出来，全程不碰解释器。

「逐字节相同」这个判据值得多说一句。它不是「看起来一样」，而是同一个输入喂给两个实现，cmp 报告零字节差异。这是这个项目对「等价」的定义，也决定了这些工具为什么算重写，而不是替代品。

对开发者意味着什么

Windows 上有一条 scripts/lomc.ps1，同样用种子加 clang，不装 Python 就能编译运行；.lomt 与 .lom 的文件类型已经注册。

语言服务还能当 CI 用：lsp --check FILE 把诊断按「路径:行:列: 错误码 标题」打到标准输出，退出码 0 或 1，可以直接接进编辑器任务或流水线。

还没做到的

一百个里程碑完成 86 个。未开始的 4 个（M37、M39、M40、M42）全部在内核侧，等内核线的排期。未达的 1 个是 M100，而它缺的不是门禁——门禁已经齐了，一条 tools/loment_audit.py 能跑完 10 条主张并落盘证据——缺的是第三方复核本身，而这件事作者无法自证。

工具链上也还有 Python：包管理器 lompkg 尚未重写，它需要 JSON 解析、目录遍历和 SHA-256，而运行时还缺 getdents；测试侧的判据仍然是 Python，那部分不影响构建和使用 Loment。

语言服务目前不提供格式化，也不做跨文件索引；lompkg 只支持本地路径依赖，没有网络仓库。这些边界写在这里，是因为 9 月 20 日交到手上的东西，应该和它声称的一样大。
