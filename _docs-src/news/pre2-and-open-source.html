Pre2：调用别的语言写的库

这一版给语言加的东西只有一个：extern fn。它是只有签名、末尾分号的顶层形式，调用点按平台 C ABI 传参——Loment 与 Loment 之间照旧走自家约定（实参走栈），只有声明了 extern 的调用点换一套。构建时用 loment build --link lib.o 把外部目标文件链进来。

两条腿，按「对方是什么」分。C ABI 那一族——C / C++ / Rust / Zig / Go / Swift / C# / Fortran——导出的是同一种符号与同一套传参约定，所以加一个语言就是加一条构建配方加一条判据。运行期那一族——Python / Java / JS / Lua——它们不是导出 C ABI 的库而是解释器，走新加的进程桥 loment/lib/proc.lomt：起一个解释器进程，把代码交给它，把 stdout 读回来。

这台机器上真跑通的： C（退出码 52）、C++（42）、Rust（42）走 --link；Python（9）、JS（7）走进程桥。Java / Zig / Go / Swift / C# / Fortran 的配方写在判据里，但本机没装那些工具链，所以是 SKIP——缺的是工具链，不是通路。这句区分很重要：机制上两条腿各自覆盖一族，"7 个语言"是保守说法。

纯 Loment 程序不受影响。它仍然是 freestanding 的——无运行时、无 libc、不需要 Python。只有声明了 extern 的程序才带外部依赖，而且它自己负责把目标文件准备好。既有程序零改动：extern 是新语法，不用它的程序一个字节都不变（语料 54/54 仍逐字节一致）。

Pre1：把两个面交给使用者

Pre1 在一天前，做的是另一类事——它把两个原先由官方说了算的面交出去。后缀不再属于语言：只有 .lom 是特殊的（L0 接口契约），别的任何后缀都是 L1 源；名字形式 use 找哪个后缀由项目根的 loment.conf 里一行 source_ext() 定。自定义命令：像 git——PATH 上放一个 loment-foo，loment foo 就能用，官方命令优先，没有注册表。

Pre1 顺带修掉三处静默错编——同一份源码，两个实现给出不同的单元。其中一处的后果值得单说：名字形式的搜索原先只认仓库相对的四个根，所以装在用户机器上（没有仓库）时 use std 一个都找不到。现在搜索分三层，第二层就是工具链自带的 store——这也是打包版第一次能写 use std。

alpha 系列到此为止。Pre1 的这两条是给别人用这门语言的口子，之后语言面不再改——所有触及冻结面的改动从此要走 docs/158 §5 那套流程。
