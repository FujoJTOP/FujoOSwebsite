站上说的，和你跑出来的，对不上。

这块看板收的东西很具体：站上写了某句话，你按它的命令跑，得到的不是它说的那个东西。不管最后是我们写错了、命令过期了，还是你的环境确实不同——先报上来，读明白之后它会带着编号进下面那张表。

提交一条 bug 看板
为什么是邮件。 这个站没有服务器，这个 origin 上也不许跑第三方脚本——两件事一起，可用的提交渠道只剩一个。代价是实打实的：没有投票，没有评论，条目由作者读完再录入。
编号不会变。 —— 一条报告的编号是它的地址，按顺序发放，不复用、不重编。你留过的链接永远指向同一条。

一条报告要带什么

这个站对「完成」的要求是可重放的命令与输出；对「没完成」的要求一样。缺了下面任何一条，报告只能停在「需要更多信息」——不是刁难，是没有它就无法判定谁对。

带什么 为什么
哪一句 页面地址，或者原文。没有这一条，我们不知道该去改哪儿。
你跑的命令 原样贴，不要整理。整理过的命令跑出来的东西，通常正是分歧所在。
你得到的输出 原样贴。错误信息是整个报告里信息量最大的部分。
你预期的输出 引用站上那句话就够了——它就是我们双方的对照物。
版本与环境 站上写的版本串；以及 OS、浏览器或工具链的版本——但只在确实相关时才要。

两条硬门槛

  • 要指向站上的一句话 —— 给不出页面地址或原文的，不进看板。这一条挡掉的是「你们应该支持 X」。
  • 要带命令与输出 —— 只有结论、没有过程的，同样不进。这一条挡掉的是「我试了，不行」。

这不是苛刻。这两样都没有，我们无法判断是站错了还是你看错了——那它就不是一条能处理的报告。

照着这个填

text 报告模板 
【哪一句】页面地址，或者原文
【命令】  原样贴，不要整理
【输出】  原样贴，错误信息别删
【预期】  站上那句话
【版本】  站上写的版本串
【环境】  OS / 浏览器 / 工具链（只在相关时填）
这些不用报： 站上有些页面本身就在讲「还没做完」——已知边界、冻结面的开放项、M100 的外部审计。那些是已知的，写在明处。但某一页把本该写的缺口写漏了，那是真 bug。

看板

每一条都带一个不变的编号、它报出时的版本、以及现在的状态。状态只有六种，含义写死；关掉的条目必须写明为什么。

还没有条目。

报进来的东西被读明白之后才会写在这里——这块板子是记录，不是收件箱。怎么报见上面。

官方 / 非官方 —— 这是这块板子上最重要的一栏。非官方 = 别人报上来的，原样收录，我们没有复现过；它是一条声明，不是我们的结论。官方 = 我们自己复现过、或明确判定过的。垃圾进不来，靠的不是事后删帖，而是这一栏始终在行上。
待确认 / 已确认 —— 收到了，还没读完 / 读过了，确实复现得出来。非官方条目只能是待确认——别人一条没验过的声明，我们无从替它下结论。
已修 —— 改完了，并写明在哪个版本。改了哪一处也会同时改文档——这个站不留下对不上的说法。
重复 / 无效 / 不予处理 —— 三种关闭方式，都要写理由：已经有人报过、报告本身不成立、或者我们决定不做。关闭不等于不认。
